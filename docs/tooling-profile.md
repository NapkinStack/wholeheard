# Tooling profile

> Tools are **adapters**, never architectural foundations.
> The OS declares **capabilities**; this file maps them onto the tools of the moment.
> Changing tool must never force a change to the kernel or the playbooks.
>
> This file is the only place in the repository where a tool name appears.

## Choice criteria

The project · security · confidentiality · reliability · cost · maturity · integration ·
and above all **the ability to be automated**. A tool useful only interactively can never
become a guarantee.

> Never add a tool because it is popular. The Prior Art Gate applies to tools too
> (`docs/os/06-decisions.md`).

## Replacement rule

Replacing a tool must touch only this file and the configuration that goes with it. If
changing tool forces a change to the kernel, a playbook or a module, the tool had become
a foundation — fix the abstraction, not the prompt.
