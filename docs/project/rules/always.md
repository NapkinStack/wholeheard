# Rules of this project — always

> Read with the charter, for every task. These rules add to what every project shares, or
> tighten it; they never repeat it. A rule that concerns one module only belongs in that
> module's `AGENTS.md`.

| # | Rule | Why | Checked by |
|---|---|---|---|
| 1 | Everything written in this repository is in English: documents, code, identifiers, commit messages, pull requests. An input kept as it was given (`docs/project/inputs/`) stays in its own language; so do the sentences the product says to its users, which are its content and are written in each language it speaks — English and French, in the one file a module keeps them in (the decider, 2026-10-13). | Decided by the decider at the discovery's intake, 2026-10-12: the product may become open source, and the framework's forms are in English. | Review. Nobody yet: no check reads a document's language. |
| 2 | A pull request is merged by the agent without waiting for the decider's approval when three things hold: its checks are green — run on the workstation by `nstack attest` and recorded on its head (`checks: attested`; the decider, 2026-10-14 and 2026-10-20: "un user peut faire son dev en interne, GitHub est un opérateur") —, `nstack pr-check` finds it compliant, and a verifier that did not write it has passed its test sheet — or it changes words only. The agent never approves a pull request, here as elsewhere. What stays the decider's: a trial on a real call, the state of a deliverable, the forge's settings. | Decided by the decider, 2026-10-13 ("oui, fusionne en autonomie sur summit uniquement"). The forge requires no approval on a private repository of this plan (`discovery.md`, constraints), so the approval was a round trip and not a barrier; the diagnosis says *unguarded* and this rule does not change that. ~~It ends when the repository is opened: the approval can then be required, and is.~~ Kept after the opening ([PDR-0002](../../pdr/0002-the-repository-opened-the-pace-kept.md), 2026-10-25), until the first contribution from outside the project or the first public build, whichever comes first. | The pull request's own checks — `nstack pr-check` requires a complete, passed record of its head (A1, A2) —, and the run that fails when a commit reaches `main` outside a pull request. Nobody refuses a merge made short of the three. |
| 3 | An agent reads a command's output through `rtk` — `rtk-oss` 1.0.1, the Apache-2.0 edition, installed on the workstation, its hook rewriting the agent's shell commands: what passes is collapsed to a count, a failure is kept. When a failure's detail matters — a test that fails, a build that breaks — it is read raw, with `rtk bypass <command>` or from the log the script writes; a long log (the shell's e2e) is written to a file and read with `grep` or `sed`, never whole. | Decided by the decider, 2026-10-18 ("fais les choix pour optimiser les tokens dans summit"), under the framework's line that a command's output is context and that the project names the tool (`.nstack/handbook/04-ai-context.md` §3). `rtk-oss` rather than `rtk`: Apache-2.0 alone, without the compression engine or the proxy that would see the provider's traffic; its telemetry is off until consented to, and stays off. | Nobody: the hook is the workstation's (`rtk init -g --hook-only`); `rtk gain` says what it saved. |
